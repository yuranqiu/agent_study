## 1. 核心概念与设计背景

### 1.1 为什么需要 A2A 协议

在单 Agent 系统中，Agent 通过 MCP 调用外部工具完成特定任务。但在多 Agent 系统中，Agent 之间需要：

- **互相发现**：知道当前有哪些 Agent 可用，各自能做什么
- **传递任务**：将复杂任务分解并委托给其他 Agent
- **共享上下文**：让协作的 Agent 能获取足够的背景信息
- **跟踪状态**：任务在多个 Agent 间的执行进度需要被跟踪

传统的工具调用（MCP）无法解决这些问题，因为工具是被动的、资源性的，而 Agent 是主动的、有状态的。

### 1.2 A2A 协议的定义

```
Agent A (A2A Client)
    ↓ HTTP + JSON (A2A Protocol)
Agent B (A2A Server)
```

**A2A = Agent-to-Agent 协议**，定义了 Agent 之间如何：
1. 发现彼此的能力（Agent Card）
2. 建立通信会话
3. 发送任务（Task）并接收结果
4. 管理协作的状态

### 1.3 与 MCP 的关系

| 维度 | MCP | A2A |
|------|-----|-----|
| 定位 | Agent → 工具/服务 | Agent → Agent |
| 场景 | 单 Agent 调用外部能力 | 多 Agent 协作 |
| 协议层 | stdio / HTTP + JSON | HTTP + JSON |
| 状态 | 无状态（调用即返回） | 有 Task 状态管理 |
| 关键概念 | Tool / Resource | Agent Card / Task / Message |

**两者互补**：一个完整的 Agent 系统通常同时使用两者：
- 用 MCP 调用工具（搜索、代码执行、数据库等）
- 用 A2A 与其他 Agent 协作（分工、委托、共享结果）

## 2. Agent Card 与服务发现

### 2.1 什么是 Agent Card

Agent Card 是描述 Agent 能力的元数据 JSON，用于服务发现。它让其他 Agent 或系统知道：

- 这个 Agent 是谁（name, version）
- 能做什么（skills, capabilities）
- 如何访问（host, port）

### 2.2 Agent Card 结构

```json
{
  "name": "code-review-agent",
  "description": "Performs code review for bugs, security issues, and style violations",
  "version": "1.0.0",
  "capabilities": {
    "streaming": true,
    "pushNotifications": false
  },
  "skills": [
    {
      "id": "python-review",
      "name": "Python Code Review",
      "description": "Reviews Python code for bugs and best practices"
    },
    {
      "id": "security-scan",
      "name": "Security Vulnerability Scan",
      "description": "Scans code for common security vulnerabilities"
    }
  ],
  "endpoints": {
    "http": "http://localhost:8001"
  }
}
```

### 2.3 关键字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| name | 是 | Agent 唯一标识名 |
| description | 是 | 简短描述，能做什么 |
| version | 是 | 版本号，用于兼容性判断 |
| capabilities | 否 | 能力标志（streaming 等） |
| skills | 是 | Agent 能处理的技能列表 |
| endpoints | 是 | 访问地址 |

### 2.4 服务发现流程

```
1. Agent A 启动时注册自己的 Agent Card 到注册中心（Registry）
2. Agent B 需要协作时，从 Registry 查询满足条件的 Agent Card
3. Agent B 根据 Agent Card 的 endpoints 建立连接
4. 通过 skills.id 选择具体处理技能
```

## 3. 协议交互流程与消息格式

### 3.1 核心对象

A2A 协议中有三个核心对象：

| 对象 | 作用 | 状态 |
|------|------|------|
| **Agent Card** | 描述 Agent 能力 | 静态元数据 |
| **Task** | 协作的工作单元 | pending → in-progress → completed/failed |
| **Message** | Agent 间的消息 | 请求/响应格式 |

### 3.2 Task 状态机

```
                 ┌─────────┐
                 │ pending │
                 └────┬────┘
                      │ Agent 接收到任务
                      ▼
                 ┌──────────┐
                 │in-progress│
                 └────┬─────┘
                      │ 任务完成或失败
                      ▼
            ┌─────────────────────┐
            │  completed / failed │
            └─────────────────────┘
```

### 3.3 交互流程

完整的两 Agent 协作流程：

```
Agent A (Client)                          Agent B (Server)
     │                                          │
     │──── discover_agent() ──────────────────>│ 获取 Agent Card
     │<──── Agent Card JSON ───────────────────│
     │                                          │
     │──── send_task(task) ────────────────────>│ 提交任务
     │     { skill: "code-review",              │
     │       input: { code: "...", lang: "py" } │
     │     }                                    │
     │<──── Task (status: in-progress) ─────────│ 确认接收
     │                                          │
     │<──── Task update (status: completed) ────│ 处理完成返回结果
     │     { output: { issues: [...], score: 85 } }
     │                                          │
```

### 3.4 消息格式

**发送任务请求**：

```json
{
  "type": "task",
  "skill": "python-review",
  "input": {
    "code": "def foo():\n    pass",
    "lang": "python",
    "options": {
      "check_security": true
    }
  },
  "metadata": {
    "requester_agent": "orchestrator-agent",
    "trace_id": "task-12345"
  }
}
```

**任务响应**：

```json
{
  "type": "task_result",
  "task_id": "task-67890",
  "status": "completed",
  "output": {
    "issues": [
      {
        "line": 1,
        "severity": "warning",
        "message": "Missing docstring"
      }
    ],
    "summary": "1 issue found"
  },
  "metadata": {
    "processing_time_ms": 1234
  }
}
```

### 3.5 Streaming 支持（可选）

如果 Agent 支持流式输出，Agent Card 中 `capabilities.streaming: true`，客户端可以通过：

```
GET /tasks/{task_id}/stream
```

获取 SSE 流式更新，而不是轮询任务状态。

## 4. Server 与 Client 快速实现

### 4.1 环境准备

```bash
pip install a2a-sdk
```

### 4.2 实现 A2A Server

```python
from a2a.server import A2AServer
from a2a.types import AgentCard, AgentSkill

# 1. 定义 Agent Card
agent_card = AgentCard(
    name="math-agent",
    description="Performs mathematical calculations and problem solving",
    version="1.0.0",
    capabilities={"streaming": False, "pushNotifications": False},
    skills=[
        AgentSkill(
            id="calculate",
            name="Calculate",
            description="Evaluate mathematical expressions"
        )
    ],
    endpoints={"http": "http://localhost:8000"}
)

# 2. 创建 Server
server = A2AServer(agent_card=agent_card)

# 3. 注册处理函数
@server.agent_handler("calculate")
async def calculate(expression: str) -> str:
    """计算数学表达式"""
    try:
        result = eval(expression, {"__builtins__": {}}, {})
        return {"result": result, "expression": expression}
    except Exception as e:
        return {"error": str(e), "expression": expression}

# 4. 启动 Server
if __name__ == "__main__":
    server.start(host="0.0.0.0", port=8000)
```

### 4.3 实现 A2A Client

```python
from a2a.client import A2AClient
import asyncio

async def main():
    # 1. 创建 Client 并连接 Server
    client = A2AClient("http://localhost:8000")
    
    # 2. 发现 Agent（获取 Agent Card）
    agent_card = await client.discover_agent()
    print(f"Connected to: {agent_card.name}")
    print(f"Skills: {[s.id for s in agent_card.skills]}")
    
    # 3. 发送任务
    task = await client.send_task({
        "skill": "calculate",
        "input": {"expression": "2 + 3 * 4"}
    })
    
    # 4. 获取结果
    print(f"Task status: {task.status}")
    print(f"Result: {task.output}")

asyncio.run(main())
```

### 4.4 带 Task 状态管理的 Server

```python
from a2a.server import A2AServer
from a2a.types import Task, TaskStatus

@server.agent_handler("analyze")
async def analyze(task: Task) -> Task:
    """带状态跟踪的任务处理"""
    
    # 设置为进行中
    task.status = TaskStatus.IN_PROGRESS
    await task.update_status()
    
    # 执行处理逻辑
    input_data = task.input
    result = process_data(input_data)
    
    # 设置为完成
    task.status = TaskStatus.COMPLETED
    task.output = result
    return task

# 处理函数
def process_data(data):
    # 实际处理逻辑
    return {"processed": True, "result": data}
```

### 4.5 错误处理与重试

```python
from a2a.client import A2AClient
from a2a.exceptions import TaskFailedError

async def client_with_retry(client, task_input, max_retries=3):
    for attempt in range(max_retries):
        try:
            task = await client.send_task(task_input)
            return task.output
        except TaskFailedError as e:
            if attempt == max_retries - 1:
                raise
            print(f"Attempt {attempt + 1} failed: {e}, retrying...")
            await asyncio.sleep(2 ** attempt)  # 指数退避
```

## 5. 与 MCP 的对比及生态定位

### 5.1 核心定位差异

| 维度 | A2A | MCP |
|------|-----|-----|
| 通信对象 | Agent ↔ Agent | Agent → Tool/Resource |
| 交互模式 | 对等协作（peer-to-peer） | 客户端-服务端（client-server） |
| 主要场景 | 任务分解、结果共享、多 Agent 协作 | 工具调用、数据获取、能力扩展 |
| 状态管理 | 有 Task 生命周期 | 无状态调用 |
| 典型协议 | HTTP + JSON + SSE | stdio / HTTP + JSON |

### 5.2 互补关系图

```
┌─────────────────────────────────────────────────┐
│                   Multi-Agent System            │
│                                                 │
│  ┌─────────────┐          ┌─────────────┐      │
│  │  Orchestrater │ ←A2A→  │ Code Agent   │      │
│  │   Agent      │         │             │      │
│  └──────┬───────┘         └──────┬──────┘      │
│         │                         │             │
│    ┌────┴────┐                    │             │
│    ▼         ▼                    ▼             │
│ ┌──────┐  ┌──────┐          ┌───────────┐      │
│ │ MCP  │  │ MCP  │          │ MCP       │      │
│ │Client│  │Client│          │ Client    │      │
│ └──┬───┘  └──┬───┘          └─────┬─────┘      │
│    ▼         ▼                     ▼            │
│ ┌──────┐  ┌──────┐          ┌───────────┐      │
│ │GitHub│  │Web   │          │ Code Exec │      │
│ │Tool  │  │Search│          │ Tool      │      │
│ └──────┘  └──────┘          └───────────┘      │
└─────────────────────────────────────────────────┘

A2A: Agent 之间的协作通信
MCP: Agent 调用外部工具
```

### 5.3 典型使用场景

**适合用 A2A 的场景**：
- Orchestrator Agent 将任务分发给专门的子 Agent
- 多个专业 Agent 协作完成复杂任务（如先搜索再分析）
- Agent 之间需要传递中间结果或共享上下文
- 需要跟踪任务在多个 Agent 间的处理进度

**适合用 MCP 的场景**：
- Agent 需要调用外部 API（天气、搜索、数据库）
- Agent 需要执行代码或命令
- Agent 需要访问文件系统中特定目录
- 与第三方服务交互（GitHub API、Slack 等）

### 5.4 A2A 的局限性

- 目前没有统一的标准实现，不同厂商的 SDK 可能有差异
- 跨语言支持需要适配不同的序列化方式
- Agent Card 注册中心需要额外的基础设施

## 6. 面试高频问题

### Q1: A2A 协议是什么？解决什么问题？

**回答要点**：
> A2A = Agent-to-Agent 协议，用于多个 Agent 之间的通信协作。
> 解决的问题：多 Agent 系统中的 Agent 发现、任务分发、结果共享和状态管理。
> 对比 MCP（解决 Agent 与工具的通信），A2A 解决 Agent 与 Agent 的通信。

### Q2: Agent Card 的作用是什么？包含哪些字段？

**回答要点**：
> Agent Card 是描述 Agent 能力的元数据，用于服务发现。
> 必填字段：name、description、version、skills
> 可选字段：capabilities（streaming 等）、endpoints
> skills 是技能列表，每个技能有 id、name、description

### Q3: A2A 和 MCP 的核心区别？

**回答要点**：
> 定位不同：MCP 是 Agent 调用外部工具，A2A 是 Agent 之间协作
> 交互模式：MCP 是 client-server（工具被动响应），A2A 是 peer-to-peer（Agent 对等协作）
> 状态管理：MCP 无状态，A2A 有 Task 生命周期
> 两者互补：一个 Agent 通常同时使用两者

### Q4: A2A 的 Task 状态机是什么？

**回答要点**：
> pending → in_progress → completed/failed
> 初始状态 pending，Agent 接收到任务变为 in_progress，处理完成根据结果变为 completed 或 failed

### Q5: 画出一个完整的 A2A 交互流程

**回答要点**：
> 1. Client 发现 Agent（discover_agent 获取 Agent Card）
> 2. Client 发送任务（send_task）
> 3. Server 确认任务（返回 pending/in-progress 状态）
> 4. Server 处理任务
> 5. Server 返回结果（completed 状态 + output）
> 6. Client 获取结果
